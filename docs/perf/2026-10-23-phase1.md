# Phase 1 performance measurements (2026-10-23)

## Environment

- Local Mac (Apple M5, macOS 27.0.1), Node v24.18.0, PostgreSQL 16.14 on localhost (trust auth, same machine as the API, so network latency is ~0).
- Database `readiness_coach_perf`, seeded by `npm run seed:perf` (user `perf-user`, 90 days ending today UTC): 28,535 health samples and 51 workouts.
  - `heart_rate` every 5 min (about 25.9k), 6 `hrv_sdnn` and 1 `resting_heart_rate` per day.
  - One staged night per day of about 7 h: 5 cycles of core/deep/core/rem/awake, 25 `sleep_analysis` segments per night (2,250 total). Real HealthKit nights can have fewer or more segments, so the sleep byte counts depend on this choice.
  - 4 workouts per week.
- API run with `npx tsx src/index.ts`, empty `LLM_API_KEY` (template advisor), single process.
- Command: `npm run measure:api -- --base http://127.0.0.1:<port> --token <API_TOKEN> --runs 30`. One warm-up call per endpoint, then 30 sequential timed calls, all with `tz=-240`. Time includes reading the full response body. Bytes are the uncompressed response body.

## Sleep trim gate

Gate: `/v1/sleep?days=90` p95 >= 300 ms or >= 200 KB.

TRIPPED on size: 246,350 bytes (about 241 KiB) is over 200 KB. Latency is well under the limit (p95 54.6 ms). A sleep-timeline task should be added to the plan. Caveat: the size depends on the seeded segment count (25 per night); with the 3-segment nights in `seedDemo.ts` it would be far smaller.
